# 核心分析：口径、校验与任务恢复

本轮实现程序化结果校验、版本化业务语义、任务阶段记录与手动恢复，并将跨场景案例接入默认测试。工作台保持回答正文简洁，技术记录在“分析详情”和左侧“分析任务”查看。

## 配置自己的业务口径

1. 先导入表格，在“表格数据”详情核对实际表名、内部字段名和字段类型。
2. 打开左侧“业务口径”，点击“新建草稿”或“导入 JSON”。可以从[收款模板](user-guide/examples/business-finance.json)、[库存快照模板](user-guide/examples/business-inventory.json)、[客服比例模板](user-guide/examples/business-support.json)开始。
3. 替换模板中的表名和字段。确认唯一键反映业务粒度，金额单位正确；不要把导入行号当作业务唯一键。模板本身不是已经验证的真实业务定义。
4. 保存后生成 v1；修改同一 id 会创建 v2、v3，旧版保持不变。保存只检查定义格式并写本机配置，不调用模型；实际字段和数据质量在执行指标时检查。
5. 新建分析后，在输入框下方选择口径，再提问。只有内置口径时不显示额外选择栏。已有会话不能直接切换业务或版本；当前问题在被阻止提交时仍保留。

内置 `ecommerce_v1` 保留原有多表电商契约、自由 SQL、资料检索和示例库。自定义口径 v1 支持 SQLite / PostgreSQL 上的**单事实表指标**，可以注册多个指标和表，分别指定求和、计数、样本均值或总分子/总分母比例。平均值不是可直接相加的量；比例不默认平均分组比率。跨表任意公式、汇率换算、跨调用全局快照和业务入库水位尚未纳入此版本。

常用字段：

| 字段 | 含义 |
|---|---|
| `id` / `name` | 稳定 id 和显示名称；口径及指标 id 在各自范围内唯一 |
| `table` / `primary_key` | 实际表名和业务唯一键；执行前检查映射，查询快照内检查重复键 |
| `date_column` | 日期字段；周期统一采用 `[start, end)`。日期文本须使用标准格式，原生时间列遵循数据库日期规则，业务时区应在数据准备时确认 |
| `aggregation` | `sum`、`count`、`average`、`ratio`；比例须提供分子和分母字段 |
| `storage_unit` | 原始存储单位。`分`、`万元`、`亿元`统一输出为元；比例输出百分比；不根据数值大小猜单位 |
| `time_behavior` | 默认 `flow`。库存、余额等设置为 `snapshot`，执行时仅允许单日范围，防止跨日累加 |
| `dimensions` / `filter_columns` | 可分组及可临时筛选的字段 |
| `filters` | 固定筛选。临时条件只能追加，不能删除原口径的约束；值通过 SQL 参数绑定 |
| `non_negative_columns` | 业务确认需要非负的字段；负值不默认删除，未声明的字段不自动套用非负约束 |
| `document_ids` | 当前业务允许检索的文档 UUID；默认为空，自定义模式不会读取其他资料 |
| `reference_date` | 默认 `today`，也可固定为 `YYYY-MM-DD`；不影响内置演示库原有日期设置 |

自定义口径下，Agent 只可使用当前版本的指标、计算器和明确授权的文档检索，不能调用自由 SQL 绕过口径。`get_business_definition` 查看定义，`query_business_metric` 由程序生成 SQL；类型、缺失、唯一键、日期和非负约束不通过时不返回统计结论。无记录和真实零值分开，分母为零的比例保持未定义。

## 查看程序校验

每条回答的“分析详情”新增程序校验记录：带单位的关键数字可以对应到 `E1.facts[0].value` 等工具结果位置。程序能发现可观察到的数字、单位或明确日期范围冲突；已确认指标与任意 SQL 别名采用不同的信任程度。

- **已识别断言通过**：识别到的检查项有对应证据，不代表整篇回答或因果解释已被证明正确。
- **部分可核对**：缺少单位或唯一对应信息、输出不完整等，未作完整认证。
- **发现不一致**：不作为成功结果或可信会话条件写入；启用模型审查时，反馈也会进入现有的一次修正与复核。
- **不适用**：例如本轮等待补充条件，或没有识别到带单位的数字；不冒充通过。

无单位数字、编号、任意表达式及完整 SQL 业务语义不在此程序校验的证明范围内。每轮最多检查前 100 个数值断言，超过时明确标为部分验证。模型审查、程序校验和业务核对仍是不同层次。

## 查看和恢复任务

左侧“分析任务”可查看读取条件、可选规划、执行、模型审查、程序校验、保存等实际阶段，以及各次尝试的计划和工具记录。完成状态表示执行已结束，结果是否可信仍要查看校验与审查。

失败、主动停止或已中断的任务可以手动恢复。界面需再次确认，说明可能产生模型费用；恢复会重新执行读取并查询当前数据，参考上次程序校验的错误反馈，**不把上次的数字当作新证据**。这是阶段级恢复，不提供数据库快照级、逐条 SQL 的无损断点续跑。任务最多 20 次尝试，当前页面最多展示最近 500 条事件，更多记录仍留在本机文件中。

口径版本或会话条件已变化时，恢复被阻止，应新建分析。仅内存会话重启后若丢失原上下文，也会阻止不安全恢复；完整模式的已确认条件由 PostgreSQL 持久保存。进程异常退出后，失联任务约 90 秒后可判为中断，打开任务列表或刷新详情更新状态。没有自动恢复或后台付费重跑。

“数据与费用说明”内可以主动勾选“复杂问题先制定计划”。默认直接分析；规划会增加模型调用，恢复使用原任务的模式。关闭页面或停止流式分析会取消正在进行的执行。

## 存储和接口

业务口径及任务元数据使用本机 SQLite 文件，默认与个人模型配置目录同级的 `workspace.sqlite3`，可用 `LOCAL_WORKSPACE_PATH` 指定位置。Docker 复用当前用户配置卷。它不含 API Key，但含业务定义、问题及执行证据，属于需要保护的业务资料；它不是 DPAPI 加密文件。原有业务数据库、文档、上传文件及 PostgreSQL 报告不迁移、不重建。新任务输出不包含 `thought` 字段，历史快照保留原样。

| 接口 | 用途 |
|---|---|
| `GET /api/v1/business-profiles` | 查看可用口径及最新版本 |
| `GET /api/v1/business-profiles/{id}?revision=1` | 查看指定版本；内置口径只读 |
| `PUT /api/v1/business-profiles/{id}` | `{expected_revision: 0, profile: {...}}` 创建首版；修改时提供当前版本，冲突返回 409 |
| `POST /api/v1/chat`、`/chat/stream` | 新增可选 `business_profile_id`；默认保持内置行为 |
| `GET /api/v1/analysis-tasks`、`/{id}` | 查看任务及阶段记录 |
| `POST /api/v1/analysis-tasks/{id}/resume` | `{confirmed: true}` 明确恢复，重新查询且可能计费 |

流式恢复也可提交原任务的 question、session_id、mode、business_profile_id 和 `resume_task_id`；服务端核对记录及执行权，运行中或完成的任务不能重复恢复。配置和任务接口限制本机、同源及回环 Host；这是本机单用户能力，不是多人账号隔离。

## 回归验证

```powershell
.\.venv\Scripts\python.exe -m eval.core_regression --out reports/core-analysis-upgrade/offline-regression.json
.\.venv\Scripts\python.exe -m pytest
node --test tests/workspace.test.cjs
```

新场景已接入默认 pytest，并有独立入口。使用合成财务、库存和客服数据、脚本模型驱动真实工具、编排和持久化，验证正确输出及错误答案被阻断。它不调用外部模型，不代表真实模型推理准确率；真实模型适配仍需要使用者自己的配置和明确授权的单独评测。
