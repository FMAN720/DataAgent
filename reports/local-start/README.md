# Windows 日常启动修复（2026-11-05）

本次报错的直接原因是 Docker Desktop 未运行：15432 和 16379 端口都没有监听。网页进程仍能启动，但 PostgreSQL / Redis 不可用；文档、导入和历史模块在应用启动时被关闭。恢复容器后，旧应用仅变为 `degraded`，这些模块需要重启应用重新初始化。

已恢复 Docker 及两个现有容器，并重启应用。复用原数据库卷、业务资料与个人模型配置。恢复后 `/api/v1/health/ready` 为 `ready`；分析库、会话、文档库、检索、导入、历史均为 `up`。首页、datasets、documents、conversations 的 GET 请求均返回 HTTP 200。没有提交聊天、连接测试、上传或重新导入请求。

新增 `start-agent.cmd` / `app.local_start`：自动定位项目和虚拟环境，按实际 CLI 安装位置唤醒 Docker Desktop，等待引擎及 PostgreSQL / Redis 健康检查后再启动工作台；已启用的模块全部就绪后才打开浏览器。依赖失败会停止；遇到旧的半可用应用会提示在原窗口 Ctrl+C 后重启；已健康的应用直接复用。入口用于已经初始化的 Windows 本机完整模式。

12 项离线测试通过，覆盖每用户安装路径、隐藏进程与路径传递、引擎失败、Compose 健康等待和失败阻断、503 探测、旧进程就绪门槛、复用、浏览器就绪门槛和启动超时。Ruff、mypy 和 `git diff --check` 通过。实际从项目父目录执行 `start-agent.cmd --no-browser` 成功定位目录并复用健康服务；实际启动新应用及拒绝旧降级应用的路径也已验证。自动唤醒代码使用模拟进程测试；本次恢复 Docker 使用相同安装路径的真实隐藏启动。没有为了测试而关闭运行中的 Docker，也没有额外打开浏览器。
