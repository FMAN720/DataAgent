# 模型获取与个人服务配置验收

本轮仅实现用户要求的模型目录获取，以及聊天、图片/OCR、文本向量三种个人配置，不实施上一轮讨论的开源项目升级方案。

## 交付

- 设置窗口分三种用途，各自选择供应商、填写基础地址和 Key、获取目录、选择模型、测试及保存。预设只填写供应商地址，不硬编码模型名称；目录不可用时可手动填写。列表不等于账户授权或用途认证。
- `POST /api/v1/model-settings/models?purpose=...` 请求兼容 `/models`，无推理或配置写入。错误不回显供应商正文或 Key，不跟随重定向、不自动重试；响应和目录大小有上限。
- 旧聊天 v1 文件保持可读，首次保存任何用途升级为 v2 三用途格式。每个 Key 独立加密，地址变化必须重新提供 Key。清除只操作选定用途，其他用途保留。
- 网页三种用途不回退使用开发者环境 Key。保存即供下一次调用使用，无需重启；已经开始的聊天、识别、检索和索引操作固定使用开始时的配置。
- 图片接口从单一供应商扩展至 OpenAI 兼容图片聊天接口；每次真实识别仍需同意外发。测试只发送 TEST 合成图片，实际解析保留文字/表格及人工核对规则。
- 向量模型可显式启用，测试自动读取实际维度。后台索引、检索和上传使用个人配置。模型改变后保留旧向量并按版本隔离；文档详情提示需要重建，用户主动发起才重建，不因保存设置批量调用 API。

使用步骤见[模型设置指南](../../docs/user-guide/model-settings.md)。专用 OCR 的非兼容协议、非兼容模型目录协议及任意供应商能力识别不在本轮范围内。CLI 直接构造客户端仍可使用脚本自己的环境设置。

## 验证

| 项目 | 结果 |
|---|---|
| Python 全量（PostgreSQL / Redis 均启用） | 最终代码 620 通过，0 失败；62.92 秒 |
| 新目录、凭据隔离与运行时测试 | 18 个；覆盖错误、旧配置升级、不借 Key、维度、请求快照、工作者配置固定及自定义视觉协议 |
| 真实数据库新增流程 | 个人向量模型的索引、检索、换模型与旧向量保留；个人 OCR 的同意外发、真实转录持久化及待人工核对 |
| 前端逻辑 | 55 通过，含获取不保存、不测试，独立用途草稿与 Key，关闭后的迟到响应，以及维度测试 |
| Ruff / 格式 / mypy | 通过；169 个 Python 文件符合格式，109 个应用及评测源文件类型通过 |
| 隔离浏览器交互 | 桌面 1440×1000、手机 390×844、窄屏 320×740，共 12 个捕获状态 |

浏览器使用已安装的隔离 Chrome，鼠标/键盘操作真实表单和下拉框，覆盖加载锁定、目录失败和手动回退、独立配置保存、合成测试、显式向量启用、两次确认清除、Escape 及关闭后的 Key 清理。所有 API 响应均为合成拦截，不修改使用者配置，不访问模型供应商。[浏览器检查记录](../../.impeccable/review/model-discovery/browser-checks.json)验证界面，不作为真实供应商可用性或识别准确率证明。

程序测试用 MockTransport 与合成数据驱动真实的客户端、OCR 审核流程、PostgreSQL/pgvector 与索引工作者。新增数据库记录有自己的来源及清理范围，不删除用户资料。没有安装新依赖、使用真实 Key 或发起付费模型请求。

最终检查及相关工作树源文件指纹见[验证记录](verification.json)。新版服务重启后，对主页、就绪状态、三种配置元数据、文档、数据集、历史及接口文档的 10 项只读检查全部返回 200，未发起供应商请求，见[本机就绪记录](runtime-smoke.json)。

静态检测仅运行一次，保留[原始结果](../../.impeccable/review/model-discovery/detector.json)。两个已有主告警分别为隐藏图片预览初始无 src，以及静态扫描无法解析 `/assets/` 链接而推断默认标题字号；其余为既有令牌解析建议。未添加忽略项、改写设计令牌或声称零告警。

独立界面收尾审查 **disposition: ship**，全部 12 张捕获有效，本轮设置表单没有待修复项。审查范围是继承视觉系统内的模型设置扩展，不是全面后端审计。见[审查记录](../../.impeccable/review/model-discovery/finish-review.md)。

[设计交接记录](../../.impeccable/review/model-discovery/design-documentation.md)核对了实际表单、样式与状态。既有 DESIGN.md 和 sidecar 保持不变，原有设置快照及文案漂移只作记录，未扩大为视觉系统重写。
