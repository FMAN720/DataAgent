# 第三轮：图片与扫描资料的核对接入

本轮解决“图片中的表格/文字无法利用”的输入缺口。完成代码、真实本地解析与数据库验证、模拟视觉接口、浏览器核对流程。**视觉模型尚未选定，真实视觉 API 未调用，不宣称 OCR 准确率或模型效果已验证。**

## 授权与安装

用户选择硅基流动视觉 API，模型待确认；明确允许仅在项目已有 `.venv` 安装 Pillow、pypdfium2 及必要依赖。

- 实际安装：Pillow 13.0.0、pypdfium2 5.14.0；PyPI wheel 下载约 7.3 MB、3.9 MB，无其他新包。
- 作用：校验/归一化图片、将扫描 PDF 页面渲染为图片；不包含本地 OCR 模型、GPU 框架或新中间件。
- 依赖声明：`requirements-vision.txt` 和 `pyproject.toml` 的 `vision` extra。未构建或拉取 Docker 镜像。
- 数据库通过既有迁移账号执行 `0005_vision_drafts` 增量迁移，仅新增识别草稿表；业务表和已有数据不改。
- DeepSeek、视觉模型、BGE-M3 本轮真实请求数均为 0。现有 Embedding 配置保持原状。

## 使用和配置

工作台：<http://127.0.0.1:18080/>。在“表格数据”或“业务文档”点击“图片 / 扫描件”。可选择保留的“合成演示-预置人工转录.png”草稿，它的文字和表格是演示程序预置的人工转录，页面与原图明确标注合成，不是模型识别结果。

上传 → 选页 → 主动同意识别（或人工转录）→ 对照原图修改文字/CSV → 保存核对稿 → 勾选已核对 → 转表格预览或本页参考资料。转表格后仍需确认字段才能导入。可识别多个指定页，但界面逐页核对、逐页发布，避免把未查看的页一起确认。

在本地 `.env` 设置以下独立项，模型和 Key 不要发送到聊天记录：

```dotenv
VISION_ENABLED=false
VISION_API_BASE=https://api.siliconflow.cn/v1
VISION_API_KEY=
VISION_MODEL=
```

选定控制台支持图片输入的完整模型 ID，填写 Key，再明确设为 true 并重启。代码不自动借用 Embedding Key，也不将 BGE-M3 作为视觉模型。当前按用户选择只允许硅基流动官方 HTTPS `/v1` 地址，不跟随重定向，不读取环境代理。

本实现要求能按提示返回正文/表格 JSON 的视觉理解模型；专用 OCR 模型可能使用不同提示或仅输出 Markdown，不能在未经适配验证时声称兼容。按[硅基流动官方视觉接口](https://docs.siliconflow.cn/docs/userguide/capabilities/vision)的 base64 `image_url` 协议实现，每次发送一个本地归一化 PNG，`detail=high`。尚未运行真实模型联调，Key 可用性、账户额度和转录质量均未验证。

离线演示：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m eval.vision_offline
```

默认只生成本地合成 PNG/扫描 PDF 和说明记录；`--persist` 才新增一份预置人工转录草稿，不调用模型、不自动发布资料。重复执行会新增草稿，按需要使用。

## 流程、持久化与异常

`VisionDraft` 独立于 `Document` 和 `UploadedDataset`；状态为 `previewed / recognizing / needs_review / failed`。草稿放在 `data/vision/`，原始来源按服务端 UUID 命名。每次读取源文件核对托管路径、大小和 SHA-256，防止来源被替换后仍发布旧转录。

识别开始前短事务锁定草稿并核对 revision，记录模型/协议 profile、所选页、租约。发起页请求前保存尝试记录，成功后逐页保存原始与可编辑副本。整次页请求有默认 90 秒总超时、响应体上限和输出 Token 上限；HTTP 错误、超时、截断或结构不合法均不会自动重试。Token 用量缺失时标为不完整，不能当成零费用；`submitted_or_unknown` 表示请求可能已发出，不能据此断言未扣费。

失败后保留成功页，人工再次确认识别时复用它们，仅请求未成功页。进程中断后租约到期可恢复为失败，不自动重新请求；租约 token 阻止旧请求回写。一个服务实例同时只执行一个识别操作，数据库版本/行锁也保护同草稿跨实例并发。修改模型不能混用既有 API 结果，需新建草稿。不同草稿/多实例间不做全局限流。

人工确认表格时，字面 CSV 与来源信息进入既有 `DatasetService.stage`；来源信息参与去重指纹，两个不同图片来源不会因相同 CSV 内容被悄悄合并。待确认字段时 Agent 仍看不到数据。导入后 `list_datasets` 返回图片来源及人工转录限制，业务查询仍使用只读账号。

参考资料只对明确选择、已经转录的页分块并保存原页码；原文件复制至既有文档托管目录，记录部分来源提示和转录哈希。不自动向量化。`allow_embedding=true` 是单独的明确选择，需要已配置的 Embedding 服务；未启用时明确失败，不偷偷退回其他模型。相同确认内容重复保存返回同一文档；首次转录保持不变，后续修改仅改编辑稿。

## 默认限制与边界

| 项目 | 默认 |
| --- | --- |
| 图片/扫描文件 | 10 MiB |
| 原图像素/边长 | 1600 万像素 / 16000px |
| PDF 总页数 / 一次主动识别 | 20 页 / 最多 5 页 |
| 预览/API 图最长边 | 2048px；去图片元数据，透明底合成白底 |
| 结果 | 每页最多 10 表，每表 50 列 / 500 行；整页转录序列化 12 万字符 |
| 模型输出 | 默认最多 4096 Token；截断不采纳，不静默当完整结果 |
| 历史草稿 | 最近 50 份；本轮不做自动清理 |

- 不支持动态图、SVG、加密 PDF，也不自动提取 DOCX 内嵌图片。文本 PDF 原有上传路径保持不变。
- 小字可能受缩放影响；没有自动裁图、旋转 OCR、跨页表头合并、复杂合并单元格还原或坐标框定位。
- 无法辨认的值应为缺失并提示；模型不遵守提示仍可能错读，必须人工核对。曲线/柱图没有标注的点值不作为精确数据入表。
- 人工确认仅表示确认转录，不保证业务事实、统计口径、完整性或因果；仍需已有质量体检和证据审查。
- CSV 编辑将空单元格按缺失值处理，保留前导零和小数字符串；CSV 不区分空字符串与缺失值。首次 JSON 转录保留供核对。
- 当前无登录、租户隔离、草稿删除/保留期限、文件杀毒或操作系统进程沙箱；仍为本机单用户工作台。原文件保留以便核对，后续权限/生命周期轮次处理。
- 不承诺请求恰好执行一次：网络/写库中断后，服务商可能已处理但本地未确认结果，人工重试可能再次收费。不会用自动重试掩盖这一点。
- 本轮没有 PDF 报告导出，也没有真实 OCR 准确率、吞吐量或费用评测结论。
