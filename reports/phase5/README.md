# 第五阶段：工作台、文档来源与检索质量

完成日期：2026-10-22。当前可打开 [本地工作台](http://127.0.0.1:18080/) 使用；本次验收服务仅绑定 `127.0.0.1:18080`。重新启动可运行：

```powershell

```

## 交付内容

| 内容 | 实现与边界 |
| --- | --- |
| 表格工作台 | 上传 CSV/XLSX、选择工作表、预览、类型确认、实际导入、状态与行进度、错误、重试及删除；前导零和精确小数保留 |
| 文档工作台 | 上传 TXT / Markdown / DOCX / 文本 PDF，填写业务日期和类型，查看原文片段与来源 |
| 日期与类型筛选 | 关键词、向量两路在数据库查询前应用相同条件；起止日均包含，未知业务日期不参与日期范围检索 |
| 来源定位 | Markdown 章节、PDF 页码、Word 章节随分块保存，经检索、引用传到响应和界面；引用片段必须属于指定文档 |
| 资料元数据修改 | PATCH 日期和类型，不重新发送正文或生成向量；业务日期与上传时间分开 |
| 资料检索与对话 | 默认本地关键词检索；Embedding 关闭时禁用界面的付费检索选项。分析对话使用现有 SSE 接口，显示过程与来源，支持停止和新对话 |
| 演示与评测 | 15 份公开可读的合成业务资料、30 校准题、30 原验收题，以及规则修改后预先固定的 20 道新确认题 |

界面复用 FastAPI 与浏览器原生 HTML/CSS/JavaScript。没有安装 React、Vue、构建工具、字体、浏览器、Redis、任务队列或新镜像，也未增加外部 CDN。前端资源随 Python 包打包。桌面、窄屏、键盘焦点、异步页面切换、错误和空状态均有检查。

分析对话提交前明确说明会发送问题、字段、查询结果到已配置聊天 API 并可能产生费用；浏览数据、上传和关键词检索不调用聊天模型。本轮未执行真实聊天模型评测，聊天链路与停止逻辑采用脚本模型和内置 Node 测试验收。

## 安装与数据库

用户明确同意仅在现有 `.venv` 安装 pypdf 及必要依赖。实际仅新增 `pypdf==6.21.2`，声明见 `requirements-documents.txt`。Word 解析使用标准库 ZIP/XML，没有安装 python-docx 或 lxml。CSV、BM25 继续使用项目已有实现，未下载安装 BM25 包或本地模型。

应用增量迁移 `0004_document_metadata`：在 `agent.documents` 新增可空 `document_date`、默认 reference 的 `document_type` 及日期 / 类型组合索引。旧资料业务日期保持未知，未拿上传时间回填。没有修改业务表、源 SQLite 文件或账号权限。启动依然不自动安装或迁移。

支持的类型值为 `reference`、`weekly_report`、`review`、`campaign`、`support`。上传以 multipart 提交 document_date / document_type；搜索以 JSON 提交 date_from / date_to / document_type。详情 GET 支持 offset / limit（最多 20 片段）与 chunk_id，拒绝跨文档引用定位。响应不暴露磁盘存储路径。

## 检索优化与实际用量

授权范围：仅使用已提交的合成资料和问题，最多 120 次 HTTP 请求（含重试）、10 万输入字符，不读取用户上传文件。实现包含目的地址与模型校验、合成输入白名单、限定文档 ID 的索引领取和检索，以及跨失败重启保留的调用预算账本。

| 本轮调用 | HTTP 请求 | 输入字符 | API 返回 input tokens |
| --- | --- | --- | --- |
| 初始 60 题评测 | 8 | 7163 | 4916 |
| 新 20 题确认 | 5 | 6521 | 4362 |
| 累计 | **13** | **13684** | **9278** |

金额未从 token 数推算，以服务商账单为准。本次每次运行内部缓存相同合成文本和问题的真实向量；阈值比较重放 PostgreSQL 的真实余弦分数，不反复请求问题向量。两轮运行分别编码了合成资料，累计用量已包含重复资料编码。临时文档、分块、向量与任务均已按本轮自有 UUID 清理，未清理其他资料。

初次评测先使用 30 题选择阈值，再对另外 30 题验收；根据已暴露的混合检索问题加入置信度检查后，另写并固定 20 道新题验证。新确认集只验证固定 0.6 阈值，不继续搜索或调参。

### 初次验收：20 道有答案、10 道无答案

| 检索方式 | 有答案 Hit@1 | Hit@5 | 无答案空召回率 |
| --- | --- | --- | --- |
| 关键词 | 75% | 100% | 0% |
| 向量，阈值 0.35 | 100% | 100% | 0% |
| 向量，校准选定 0.6 | 90% | 90% | 90% |
| 原混合，阈值 0.6 | 90% | 100% | 0% |

阈值提升会漏掉部分可回答问题；不能只报告过滤率提高。原混合检索即使向量没有高置信候选，也会返回关键词命中，所以提高向量阈值不能单独解决这一问题。

### 新确认集：10 道有答案、10 道无答案

| 检索方式 | 有答案 Hit@1 | Hit@5 | 无答案空召回率 |
| --- | --- | --- | --- |
| 原混合，阈值 0.35 | 100% | 100% | 0% |
| 原混合，阈值 0.6 | 100% | 100% | 0% |
| 加置信度检查的混合，固定 0.6 | 100% | 100% | **60%** |

新规则在有该模型完成索引、且候选全部低于阈值时返回空结果，不让关键词候选绕过置信度检查。没有索引、Embedding 关闭或 API 故障时，仍明确说明原因并使用原关键词降级；服务故障不被伪装成已判断无答案。

当前默认 `RAG_BGE_M3_MIN_SIMILARITY=0.6` 仅针对 BAAI/bge-m3；其他模型沿用通用 `RAG_MIN_SIMILARITY`。`RAG_HYBRID_REQUIRE_VECTOR_MATCH=true` 控制混合检索检查。**自动 Embedding 持续为 false**，改进不会自动向外部发送现有文档。

仍有 4 / 10 道新无答案题返回候选；日期、相似度或引用存在，都不能证明片段支持最终结论。这里的“无答案空召回率”只是检索结果为空的比例，不是最终回答拒答准确率。文档中“没有提供该资料”的段落也可能被召回，是否能据此正确拒答需在下一阶段回答评测中区分。

完整结果：[初次评测](retrieval.json)、[新题确认](retrieval-confirmation.json)、[持久预算账本](embedding-budget.json)。原初次报告记录的是当时的旧阈值配置，保留历史结果不回写。

## 使用说明与限制

1. 表格页上传，Excel 可填写工作表名；初次预览后返回可选表名。核对字段后点击确认，再等状态变为“可分析”。同一文件不同工作表是不同数据源，旧预览不会自动删除。
2. 文档页上传时填写业务日期和类型，之后可在详情修改。演示资料位于 `app/demo/documents/`，manifest.json 给出推荐日期和类型；不会自动混入用户资料库。
3. 检索页默认本地关键词。打开原文来源可核对对应片段；PDF 有页码，Word 按章节和片段定位，不能凭排版猜页码。
4. 分析对话仅在主动提交时调用聊天 API。已完成表格可通过“分析这份数据”预填问题，该操作自身不提交模型请求。

PDF 不含 OCR，不支持扫描件、加密文件；页数、文本长度和单页内容设有限制，但没有实现操作系统级的恶意文件资源沙箱。DOCX 仅提取正文段落和表格文字，不还原图像、批注、页眉页脚或真实排版页码；计算型表格应导出 CSV/XLSX。

演示资料明确标为合成；种子系数是数据生成权重，不能当作实际增长率或真实因果证明。新页面尚未完成生产鉴权、多租户隔离或完整无障碍审计。当前资料列表为最近 100 份，表格列表为最近 50 份；大规模分页、生命周期清理和部署完善留给工程化阶段。

下一轮按原计划进入分析能力：归因下钻、歧义澄清、数据与文档冲突处理，以及逐项证据审查。真实最终回答质量、规划/反思完整费用统计及综合消融实验仍未完成。
